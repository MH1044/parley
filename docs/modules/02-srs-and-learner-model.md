# 02: SRS and learner model

## Goal

The core knows what the learner knows. Items from the syllabus become FSRS cards; every review is
logged and scheduled; skill mastery and states drive the learning path; an adaptive placement test
of 12 to 20 questions estimates where to start and a CEFR level. All of it is deterministic and
offline.

## Design notes

- Rating mapping: `wrong` → Again; `almost` (accent, typo, article, or an AI "almost") → Hard;
  `correct` with a hint → Hard; `correct` → Good; `correct`, no hint, exercise type `pick_meaning`
  or `match_pairs`, `response_ms` ≤ 2,500 → Easy; learner override ("I was right") → Good.
- Due queue: cards with `due ≤ now`, ordered by retrievability ascending, then `due`, then item id.
- Mastery of a skill: the mean of retrievability over all its cards, with cards of unintroduced items
  counting 0. States: **available** when every `requires` skill (or, if empty, the previous skill in
  syllabus order; the first skill always) is practised, mastered or tested out; **learning** when at
  least one item is introduced; **practised** when every item has at least one review; **mastered**
  when practised and mastery ≥ 0.85; otherwise **locked**.
- Placement (Levitt 1971): skills of the course in syllabus order, indices 0 to N−1. Start at
  `i = N / 4` (integer), `step = max(1, N / 4)`. Ask the skill's first vocabulary item, translated to
  English and graded offline (almost counts as correct). After an answer, if its correctness differs
  from the previous answer's, record a reversal at the current index and set
  `step = max(1, step / 2)`; then move `i = min(N−1, i + step)` if correct, `max(0, i − step)` if
  wrong. Stop at 20 questions, or at 12 or more with at least 6 reversals, or early after 4 wrong
  answers in a row at index 0 (a kindness to beginners; below the 12-question floor on purpose).
  Estimate: with 3 or more reversals, the mean of the reversals after the first two, rounded half
  up; otherwise the mean of the last 4 question indices, rounded half up. Skills below the
  estimate are tested out: each of their cards gets one review rated Good at the placement time
  with `exercise_type = "placement"`. CEFR label: estimate < 3 → "Pre-A1"; else "around " plus the
  estimate skill's `cefr`.
- Reference values for FSRS come from `py-fsrs` (version recorded in the JSON), not from the Rust
  code. Verify the `fsrs` crate's licence (BSD-3-Clause on 2026-09-29) and API version here.
- Decisions are filled in here during implementation.

## Acceptance tests

Golden cases in `tests/cases/02-srs-and-learner-model/`; code tests in
`crates/parley-core/tests/m02_srs_and_learner_model.rs`.

1. Migration on an empty file creates the seven tables with the columns of ARCHITECTURE §4
   (`PRAGMA table_info` compared) and `user_version` 1; a file with `user_version` 99 gives "This
   data file was written by a newer Parley. Update Parley to open it."
2. `start_course` twice gives the same item count; introducing an item creates exactly two `new`
   cards; a syllabus with one example removed and version 2 marks that item retired and keeps its
   two cards.
3. A new card's first review sets stability to `w[0]`, `w[1]`, `w[2]`, `w[3]` of the crate's default
   parameters for Again, Hard, Good, Easy (tolerance 1e-9; FSRS definition of initial stability).
4. At desired retention 0.90 and no fuzz, every scheduled interval equals `max(1, round(S))` days,
   capped at 365 (property over 1,000 seeded rating sequences; FSRS defines S as the interval at
   which recall falls to 90%).
5. The five scenarios in `fsrs_reference.json` (py-fsrs): stability and difficulty after each
   review within relative tolerance 1e-4.
6. `rating_for` returns each row of the Design notes table (seven cases).
7. After 500 seeded reviews over 40 items, `replay(review_log)` equals the `cards` table exactly;
   `parley srs replay` on the exported log prints the same cards (golden).
8. A fixture of five due cards with known stability and elapsed days is queued in ascending
   retrievability computed from the FSRS forgetting curve at the crate's parameters.
9. A skill of 4 items where 2 items have cards of retrievability 0.9, 0.8, 0.7, 0.6 → mastery
   (0.9 + 0.8 + 0.7 + 0.6) / 8 = 0.375 (tolerance 1e-9).
10. Skill states on `syllabus-mini`: at start skill 0 is available and skill 1 locked; after one item
    of skill 0 is reviewed, skill 0 is learning; after all its items, practised, and skill 1 available.
11. Placement on `syllabus-mini` (N = 80), as a golden case through `parley placement simulate`, with a learner correct exactly below index 23: questions
    at 20, 40, 30, 20, 25, 23, 21, 22, 23, 22, 23, 22; reversals 40, 20, 25, 21, 23, 22, 23, 22;
    estimate round(136 / 6) = 23; 12 questions; skills 0 to 22 tested out.
12. Boundary 0 → questions at 20, 0, 0, 0, 0; stops after 5; estimate 0; label "Pre-A1". Boundary
    80 → 20 questions ending at 79; estimate 79; label "around A2" (the mini syllabus's last skill is A2).
13. 200 seeded learners with slip 0.1 and uniform boundaries: ≥ 90% of estimates within ±4 of the
    boundary; every run asks 12 to 20 questions or exits early at index 0.
14. Tested-out cards each have one log entry with `exercise_type` "placement" and rating Good, and a
    due date `round(w[2])` days after the placement time.
15. `local_date` with the clock at 2026-03-29T00:30Z: offset +60 → 2026-03-29; offset −300 → 2026-03-28.
16. No source file under `crates/` contains `UPDATE review_log` or `DELETE FROM review_log`
    (append-only, invariant I6).
